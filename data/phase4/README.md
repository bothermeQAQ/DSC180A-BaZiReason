# Phase 4 data

Everything here is generated by code from the project's generators and lunar-python; nothing is copied from a contest or a person's reading. Hashes are in each folder's `manifest.json`, and `tests/test_phase4.py` checks them. Design and frozen rules: [`docs/phase4_preregistration.md`](../../docs/phase4_preregistration.md).

| Folder | Years | Rows | Role |
|---|---|---|---|
| `train_v1/` | training | 3,715 train, 179 valid | approach A, continual fine-tuning from Phase 3 round 3 (`p4_train_v1`) |
| `valid/` | validation | `p3` 240, `p2` 306, `indep` 140 | adapter selection only |
| `final_test/` | test | `p3` 788, `p2` 484, `indep` 280 | untouched until the selection was frozen; scored once |

## Why a new test split

Every earlier test split had been read while diagnosing a round:
- Phase 3 round 3 was chosen after its test results were inspected.
- `p2check_v1` informed that choice.

None of them can give an untouched estimate any more. `final_test/` uses new seeds in the test-year block and drops any prompt identical to an inspected row. `scripts/phase4/run_eval.py` refuses to score it before `results/phase4/selection.json` exists, and every access is logged to `results/phase4/final_test_access.jsonl`.

## The three parts

- **`p3`:** the Phase 3 rule-reasoning families, from the Phase 3 test generator (version 1), with the same mix as the Phase 3 test split. A third of the questions use a test-only wording.
- **`p2`:** the Phase 2 calendar families, from the Phase 2 generator (version 2), with test-only templates and zones.
- **`indep`:** the independent rule questions (`bazireason.indep_rules`).
  - **Labels:** from lunar-python's `EightChar`, a third-party implementation, not from the project's rule code. The conventions are the same; a test confirms that the project's code gives the same answers on the validation part.
  - **Kinds (seven):** Ten God of a stem, Ten God of a branch's main qi, hidden stems, twelve-stage position, 旬空, luck direction, element count.
  - **Wordings:** two per kind, written for Phase 4. They and the bare chart format ("辛卯 乙未 庚辰 庚辰") never occur in any training set.

## `train_v1/`: what approach A trains on, and why

The composition follows the error analysis in `results/phase4/error_analysis.json`, which read only saved outputs on inspected splits:

| Measured failure of round 3 | Rows in `p4_train_v1` |
|---|---|
| Time zones that need the tool: 2/28 right (Phase 2: 18/28); it converted unknown offsets from memory, wrongly | `tz_needs_tool` 120 with `tz_known` 100 as the contrast |
| Solar-term boundaries 66/112 (Phase 2: 75/112), partly by claiming "seconds required" when the 节 is minutes or hours away | `jie_boundary` 220, `jie_window` 120 |
| Verification 147/184 and counterfactuals 68/84 (Phase 2: 154 and 74) | `verify` 220, `counterfactual` 160, `internal` 100 |
| Five-element counts answered with the strength procedure (9 of 14 errors) | a procedure header on every rule answer (`【规则】五行计数：…`), `rule_elements` 50 and `rule_strength` 40 of the 300 Phase 2 rule rows |
| Seen wording 74% vs unseen 52% | a third of rule questions rewritten: other pillar formats, lead-ins, 日元 for 日主 |
| Book titles in answers | none (wording version 4) |

In total, 2,245 rows (60%) replay Phase 2 families and 1,470 are Phase 3 families. 337 questions are rewritten. Starting adapter: Phase 3 round 3; peak learning rate 5e-5.

Known overlap: 3 validation and 5 final-test prompts are also training prompts, all finite-space table drills.
