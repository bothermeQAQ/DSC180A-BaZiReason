# Phase 3 data

Phase 3 teaches traditional rule reasoning on top of the Phase 2 calendar skills. Everything in this folder is generated by code; nothing is copied from a contest, a website or a person's reading.

## `knowledge/rules_v2.json`: sourced rule cards

Twelve new rule cards (the eighteen Phase 2 cards in `../phase2/knowledge/rules_v1.json` are unchanged). Build and verify with `python scripts/phase3/build_knowledge.py --fetch`.

| Kind | Cards | Examples |
|---|---:|---|
| `deterministic_table` | 3 | Ten-God class relations, 禄 / 阳刃 / 天乙贵人, flow-year relations (伏吟, 天克地冲, 太岁) |
| `declared_convention` | 8 | named Ten-God pairings, 透干 and 通根, month-order pattern by 透干, 扶抑, simplified 调候, 格局用神, 驿马 / 桃花 / 华盖, what counts as a year "引动" an area of life |
| `traditional_association` | 1 | which pillar stands for which relatives (宫位) |

- **Quotations.** 20 short passages are quoted from 《渊海子平》, 《三命通会》 (卷二, 卷三), 《滴天髓》 and 《穷通宝鉴》, all public-domain works, as transcribed on zh.wikisource.org (retrieved 2026-11-11). The build script checks that every quotation occurs in the downloaded page and records each page's SHA-256. Transcription errors of that source are kept as they are.
- **No quotation available.** 《子平真诠》 was not on Wikisource, so the two cards that rest on it (`R-GJ-02`, `R-YS-03`) cite the work without quoting it.
- **Statements are paraphrases.** The Chinese rule statements are this project's wording. No domain expert has reviewed them.
- **Schools are kept apart.** 扶抑, 调候 and 格局 are three separate functions in `bazireason.deep_rules`; the code never merges them into one "用神".
- **Classical outcome claims are not adopted.** Where a quoted verse attaches a life outcome to a configuration, the card says so and the code only reports whether the configuration is present.

`python scripts/phase3/build_dataset.py --check` regenerates the three files in memory and compares hashes. Seed 2026111201.

### Why these families

The Phase 2 answers showed three root causes (see `docs/phase3_progress_report.md`). Each family answers one of them.

| Family | Train rows | Root cause it addresses |
|---|---:|---|
| `drill` | 1,500 | Rule errors were table-recall errors (wrong 生克 direction, wrong 刑 / 害 partner). One table row per question, recited in the answer: 15 kinds. |
| `gods` | 350 | Ten Gods of every stem and hidden stem, then the named pairings among the three stems. |
| `strength`, `pattern`, `yongshen` | 680 | 得令 / 得地 / 得势 with every hidden stem written out; month-order pattern by 透干; 用神 under one named school. |
| `interact` | 400 | A reference card per branch, then every pair, with adjacency. |
| `flow` | 500 | One flow year against the chart: pillar, Ten God, relations with each branch, 伏吟, 天克地冲, 太岁, luck pillar when the tool block gives it. |
| `domain` | 300 | Traditional view of marriage, career, wealth, study and children: stars, palace, years that match a declared trigger rule, and an explicit statement that no event is predicted. |
| `claims` | 450 | Check three or four statements about a chart: correct, wrong (with correction) or unverifiable. |
| `ambig` | 450 | Questions without a unique answer, each paired with a near-identical question that has one (no school named for 用神, unknown hour, unknown gender, which branch a star is counted from, "is this a good chart"). |
| `mcq3` | 500 | Contest-style questions whose key follows from one or more rule applications (9 kinds). |
| `dialog` | 260 | Second and third turns on one chart: follow-up, unsupported pushback, correcting an injected error, declining a prediction. |
| `overview` | 160 | A whole-chart summary over the verified tool block, sorted into computed, convention and not determinable. |
| `strict_audit` | 700 | The benchmark's JSON-only format with a supplied tool answer that is clean (half) or wrong in a way the chart itself exposes. |
| `replay_*` | 683 | New samples of the Phase 2 families, so the calendar skills are rehearsed. |

### How labels are produced

- **Rule answers** come from `bazireason.rules` and `bazireason.deep_rules`. The answer text writes the table rows and intermediate values it uses (`bazireason.deep_tasks`).
- **Strict audit answers** are the unchanged engine's result for the request. Training uses only errors that the supplied chart itself exposes: a 五鼠遁 or 五虎遁 violation, a year pillar that contradicts the year, an hour branch that contradicts the clock, a day shifted across the 23:00 / 00:00 boundary, or a confident chart for an ambiguous request. A month taken from the wrong side of a solar term cannot be seen without the instant and is never a training target.
- **Areas of life** have one kind of target: the traditional correspondence, where it sits in the chart, which years match the declared trigger rule, and a statement that the event cannot be determined. No outcome for any person is invented.

### Leakage guards (tested in `tests/test_phase3.py`)

1. **Year blocks and exclusions** are those of Phase 2 and use the same sampler: disjoint years per split, no date within seven days of an evaluation case, none within one day of a BaziQA birth date. The test checks every ISO date written in a user turn.
2. **No contest material.** The generator reads no contest question, option, answer or explanation; a test confirms that no BaziQA question text and no `benchmark_v3` timestamp occurs in the dataset.
3. **Unseen wordings.** Every question has three wordings; the third occurs only in the test split.
4. **Unseen error kinds.** The test-only family `strict_shift` (180 rows) adds two kinds of tool error that never occur in training and reverse the association between time of day and kind of error: a day pillar shifted at midday, and an hour stem shifted near midnight.
5. **Known overlap.** Table drills have a small, finite question space (for example 100 Ten-God pairs), so a drill question can recur across splits. No other prompt is shared between the test split and the other two.

### Limits

- Templated Chinese: the model learns procedures and a fixed answer form more than free conversation.
- The strength count, the 透干 pattern rule, the simplified 调候 rule and the trigger rule are this project's declared conventions. A practitioner may reach different conclusions.
- Charts are sampled from real calendar dates in the split's years, but rule tasks show only the four pillars.

## `dev_v1/dev.jsonl`: development split

627 rows from the validation years with a different seed. It was used to read the first round's errors and decide on a second round, so that the test split stayed unopened until an adapter had been selected.
