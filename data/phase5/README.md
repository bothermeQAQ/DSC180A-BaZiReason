# Phase 5 data

Everything here is generated by code, except the blind questions, which an untuned local model wrote. Nothing is copied from a contest or from a person's reading. Design and frozen rules: [`docs/phase5_preregistration.md`](../../docs/phase5_preregistration.md). Hashes are in each folder's `manifest.json`, and `tests/test_phase5.py` checks them.

| Folder or file | Role | Contents |
|---|---|---|
| `valid/` | selection only | `rules.jsonl` 202, `indep.jsonl` 140, `calendar.jsonl` 388 |
| `sealed/` | scored once, after `results/phase5/selection.json` | `rules.jsonl` 411, `indep.jsonl` 280, `calendar.jsonl` 818 |
| `blind/<split>.jsonl` | dev 195, valid 156, sealed 314 | questions in users' own words |
| `blind/<split>_attempts.jsonl` | provenance | every writer attempt, accepted or rejected, with the reason |
| `convo/<split>.jsonl` | dev 20, valid 30, sealed 60 | five-turn dialogues |
| `train_v1/` | G1 training | 2,260 train, 100 loss-validation rows |

Development data for Phase 5 is `data/phase4/final_test`, which was read during the Phase 4 review, plus `blind/dev.jsonl` and `convo/dev.jsonl`.

## The parts

- **`rules`:** Phase 3 rule families (Ten Gods, strength, pattern, 用神 by school, relations, flow years, areas of life, overview, three ambiguity kinds). Only families whose rule-code plan reproduces the stored label exactly are included (`p5_eval.template_intent`). Each row carries its oracle intent.
- **`indep`:** rule questions labelled by lunar-python, in wordings never used in training (`bazireason.indep_rules`).
- **`calendar`:** Phase 2 chart requests (`task == "chart"`), for the model-alone track. They include answerable requests and requests without a single answer (ambiguous, needs a tool, invalid, unsupported).
- **`blind`:**
  - **Who writes them:** the writer model is Qwen3.5-4B (4-bit, untuned). It gets a chart and a plain-language description of what a user wants to know, and writes one question in its own words. It never sees a project template.
  - **Filters,** fixed before generation: length, a question form, no prompt echo, the answer not given away, and the target named (pillar, year, star, school or domain).
  - **Labels:** from the rule code for the intended intent.
  - **Coverage:** 20 intent classes, including declined predictions and questions without a unique answer.
  - **Why not MiniCPM:** MiniCPM5-2B, the other available model family, was tried first and produced unusable questions.
- **`convo`:** five turns per dialogue, each with a check the code can decide:
  1. a blind question;
  2. "why" or "simpler";
  3. a pushback with a wrong value;
  4. a prediction request;
  5. a different computable question.

  Turns 2–5 use fixed phrasings (`scripts/phase5/convo.py`).

## Leakage guards

- **Year blocks:** the validation and sealed splits use their own year blocks (validation years and test years) and new seeds. Every prompt of any earlier split is excluded.
- **G1 training rows:** from the training years. They contain no blind question, no independent-question template and no conversation phrasing, and share no prompt with the validation or sealed splits (`test_g1_training_data_has_no_evaluation_wording`).
- **Sealed rows** are not read before the sealed runs; the scripts print only counts and hashes.

## `train_v1/` (G1)

Written only by the rule code, in the system's prompt format (version 2):

| Rows | What they teach |
|---:|---|
| 700 | answer a routed question from the supplied conclusion |
| 400 | pick the right facts from the full fact sheet |
| 260 | keep the verified answer on a follow-up or a pushback |
| 100 | decline a definite personal prediction |
| 800 | replayed `p4_train_v1` rows (calendar and rule questions, model alone) against forgetting |

Rebuild and check:

```bash
python scripts/phase5/build_train.py --check
```
